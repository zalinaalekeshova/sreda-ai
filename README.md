# sreda.ai

Локальный сайт-портфолио: **15 постеров и 3 видеоклипа**.
В **POSTER 01** добавлен постер осеннего барного меню, в **FILM 01** — мультфильм
из `1008.mov`; остальные работы пока с заглушками.
Тёмная интерактивная 3D-сцена, созданная по предоставленной записи экрана.

## Запуск

Нужен Node.js 20 или новее. Установка npm-пакетов не требуется.

```sh
npm run dev
```

Откройте **http://localhost:4173**. На этом Mac можно также дважды нажать на
**«Открыть sreda.ai.command»** в Finder. Не открывайте `index.html` через `file://`:
браузер блокирует загрузку ES-модулей без HTTP-сервера.

## Что реализовано

- Кольцо со знаком S, вращение, хроматические отражения и движущиеся ленты.
- Белые следы за мышью на первом экране: пучок лент с яркими кончиками, плавное затухание.
- Проявление крупной типографики при прокрутке.
- Спиральная галерея с перспективой, глубиной и инерцией.
- Металлическая позвоночная колонна и цветные облака частиц.
- Переход к нижнему порталу, пространству экспериментов и контактам.
- Фильтры ALL WORKS / POSTERS / MOTION, отдельный каталог всех 18 работ.
- Открытие работ, переход частицами, предыдущая / следующая работа,
  управление стрелками и Escape, прямые ссылки вида `#project/poster-01`.
- Справа от работы — панель с описанием и фотографиями референсов продукта.
  На телефоне она находится под работой. Фото открываются в увеличенном виде.
- Нативный видеоплеер для добавленных файлов; пустые блоки честно помечены.
- Форма клиента в CONTACT: имя, телефон, тип заказчика и необязательное описание задачи.
  Обработчик Google Apps Script сохраняет заявки в Google Sheets и уведомляет в Telegram.
- Мобильная версия, клавиатурная навигация, `prefers-reduced-motion`,
  остановка рендера в скрытой вкладке и CSS-режим без WebGL.
- Локальные шрифт и Three.js: внешние CDN в работе сайта не используются.

## Как добавить работы

1. Положите изображения и клипы в `assets/media/`.
2. Откройте `src/content.js`.
3. В нужной работе заполните `title`, `src`, `cover`, `description`.

Пример записи постера:

```js
{
  id: 'poster-01',
  title: 'NEW WORLD',
  type: 'poster',
  year: '2026',
  src: './assets/media/poster-01.webp',
  cover: '',
  accent: '#8397ba',
  description: 'Описание работы.',
  references: [],
}
```

В текущем файле 15 постеров создаются через `Array.from`. Можно заменить весь
массив `works` на массив явных записей, сохранив уникальные `id`.
Для видео используйте `type: 'video'`, `src: './assets/media/film-01.mp4'`,
а в `cover` укажите обложку. Рекомендуется H.264 MP4 или WebM. Для больших
клипов можно указать HTTPS URL с видеохостинга/CDN. Сервер поддерживает
HTTP Range для перемотки локальных видео.

### Описания и референсы

Для каждой работы задаются собственные `description` и `references`.
Фотографии положите в `assets/references/`, а в конце `src/content.js` добавьте
блок с нужным `id` (например, `poster-01` или `film-01`):

```js
Object.assign(works.find(work => work.id === 'poster-01'), {
  description: 'О чём работа и какой продукт показан.\n\nИдея и детали проекта.',
  references: [
    {
      src: './assets/references/product-front.jpg',
      alt: 'Исходная упаковка продукта спереди',
      caption: 'Продукт до создания постера',
    },
    {
      src: './assets/references/product-detail.jpg',
      alt: 'Фактура и детали упаковки',
      caption: 'Цвет и материал',
    },
  ],
});
```

`alt` описывает фото для скринридера, `caption` показывается под ним.
Число фотографий не ограничено двумя: можно добавить другие записи в массив.
Нажатие увеличивает фото; стрелки перелистывают референсы, Escape закрывает
увеличенное фото и возвращает к работе. Длинная панель прокручивается.
Пока `references: []`, отображаются два пустых места. В POSTER 01 уже добавлено
исходное фото шести коктейлей из бара; оно открывается целиком по нажатию.

Контакты задаются в объекте `site` в том же файле. Пустые ссылки скрываются.

## Форма и заявки

Форма находится в разделе CONTACT. Обязательны имя, телефон и тип заказчика.
Успех показывается только после подтверждения обработчиком. При ошибке данные
остаются в форме; повторная отправка того же запроса не создаёт вторую строку.
Google Sheets и бот `@sreda_ai_requests_bot` подключены; реальная отправка
проверена 19 октября 2026 года.

Для подключения используется отдельный Google Apps Script. Код, порядок настройки
и ссылки на созданные таблицу и проект: [инструкция подключения](integrations/google-apps-script/README.md).
В `site.formEndpoint` файла `src/content.js` указывается только публичный URL `/exec`.
Токен Telegram хранится в свойствах Apps Script и не должен попадать в файлы сайта.
Пока endpoint пуст, форма сообщает, что приём заявок ещё не открыт.

## Сборка и GitHub

```sh
npm run check
npm run build
```

Готовый статический сайт — в `dist/`. Он совместим с обычным статическим
хостингом, включая GitHub Pages; все пути относительные. Загружайте именно
содержимое `dist/`. Сервер Node на хостинге не требуется; `server.mjs` нужен только
для локального предпросмотра. Приём заявок обслуживается отдельно развёрнутым
Google Apps Script; папка `integrations/` в публичную сборку не включается.

Workflow `.github/workflows/pages.yml` проверяет исходники, собирает `dist/`
и публикует сайт через GitHub Pages после каждого push в `main`.
В настройках репозитория источник публикации Pages должен быть **GitHub Actions**.
Обычный цикл обновления:

```sh
npm run check
npm run build
git add .
git commit -m "Update portfolio"
git push origin main
```

По просьбе владельца после завершённых и проверенных правок агент коммитит
изменения и делает обычный push; договорённость записана в `AGENTS.md`.
Изменения обработчика Google Apps Script публикуются отдельно от статического сайта.

Оригинальная запись и временные кадры анализа не входят в репозиторий.
Съёмка использована как визуальный референс, её материалы не встроены в сайт.
Индивидуальные 3D-модели, освещение и шейдеры исходного сайта недоступны из
записи, поэтому сцена реконструирована процедурно. Это реализация композиции
и поведения по референсу, а не исходный код и не пиксельная копия оригинала.
