## Подключение

1. В Apps Script замените содержимое файла `Код.gs` на `Code.gs` из этой папки
   и сохраните. Часовой пояс проекта — `Asia/Almaty`; среда — V8.
2. В **Настройки проекта → Свойства скрипта** сохраните:

   | Свойство | Значение |
   | --- | --- |
   | `SPREADSHEET_ID` | `1PHDN5x3e6nBnV3jkkttOh2I6PbE7D9d5Nv0u5TtxrNg` |
   | `SHEET_NAME` | `Sreda заявки` |
   | `TELEGRAM_BOT_TOKEN` | Токен из BotFather, вставить только здесь |

3. В личном чате с ботом отправьте `/start`. Запустите функцию `connectTelegram`
   из редактора Apps Script. Она проверяет имя бота и берёт единственный личный
   чат с командой `/start`, сохраняет `TELEGRAM_CHAT_ID`, форматирует таблицу и
   создаёт триггер повторной отправки каждые 5 минут. Сообщения ботом на этом шаге
   не отправляются. Если `/start` прислали несколько людей, скрипт остановится:
   задайте свой `TELEGRAM_CHAT_ID` вручную и запустите `setup`.
4. Google запросит разрешения на работу с таблицами, обращение к внешнему сервису
   Telegram и запуск триггера. Авторизацию выполняет владелец. `appsscript.json`
   содержит явный список этих разрешений для переноса проекта; редактор также
   может определить их автоматически по коду.
5. **Начать развертывание → Новое развертывание → Веб-приложение**.
   Выполнять от имени владельца, доступ — **Все**. Это открывает приём новых
   заявок для посетителей сайта; сама таблица остаётся закрытой. GET не возвращает
   содержимое таблицы, токен или настройки. Авторизуйте и завершите развёртывание.
6. Скопируйте URL с окончанием `/exec` в `site.formEndpoint` (`src/content.js`).
   URL `/dev` работает только для редакторов и для сайта не подходит.
7. Выполните `npm run check` и `npm run build`. Отправьте явно помеченную тестовую
   заявку через CONTACT; проверьте строку в таблице и уведомление от бота.
   Сборку `dist/` и архив обновляют после изменения endpoint.

После редактирования обработчика создайте новую версию существующего развертывания,
чтобы сохранить тот же URL. Токен не включать в `content.js`, GitHub, снимки экрана
или текст переписки; свойства скрипта доступны редакторам проекта, поэтому права
редактирования проекта стоит оставлять только владельцу.

## Хранение и повторные попытки

Столбцы A–F содержат дату, ID заявки, имя, телефон, тип заказчика и задачу.
G–I — статус Telegram (`pending`, `sent`, `failed`), число попыток и время последней.
Строка сохраняется до обращения к Telegram. При сбое уведомления скрипт делает
до 8 попыток с задержкой. Ручной запуск `retryTelegram` возобновляет отправку
строк со статусом `failed`; уже отправленные пропускает.

Один ID запроса соответствует одной строке. При неопределённом сетевом результате
Telegram возможно повторное уведомление, так как Bot API не гарантирует
идемпотентную отправку; ID помогает отличить повтор от новой заявки.
Длинное описание в Telegram сокращается, полное остаётся в таблице.

Endpoint публичный, поля проверяются на сервере, формулы из текста экранируются.
Форма не имеет CAPTCHA; Apps Script и Telegram подчиняются своим квотам. При
большом объёме спама потребуется отдельная защита/серверный обработчик.
